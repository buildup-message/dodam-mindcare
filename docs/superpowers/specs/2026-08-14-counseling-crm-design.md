# 도담마인드케어 상담센터 CRM — 설계 스펙 (Phase 1: 일정·결제기록)

## 배경 및 목표

도담마인드케어 상담센터는 현재 상담사 4명(대표원장 최지혜, 원장 손선재, 황성현, 최윤정)이 개인상담과
그룹상담(사회성·슬로우리딩)을 병행하고 있다. 예약 일정과 상담비 결제 현황이 선생님·운영자 간에
공유되지 않아, 방 가용성 확인·결제 확인이 어렵다. 이를 위해 다음 두 축을 갖춘 내부 CRM을 만든다.

1. **상담 일정 공유·관리** — 선생님별 예약(내담자·시간·방)을 전원이 보고, 신규/수정/취소할 수 있다.
2. **상담비 결제 기록** — 개인/그룹, 성인/아동청소년, 일반/바우처 상담의 결제 내역을 언제·얼마·누가
   냈는지 기록·조회한다.

## 범위 (Scope)

**Phase 1 (본 스펙)**: 일정 공유·관리 전체 + 결제 "기록"(장부) — 실제 카드결제 처리는 포함하지 않는다.

**Phase 2 (별도 스펙, 추후 진행)**: 내담자가 실제로 부담하는 금액(일반 상담비·바우처 본인부담금)에
대한 PG(결제대행사) 연동 — 카드결제를 앱 안에서 바로 받는 기능. 바우처 지원금(국가부담분)은 국가
바우처 시스템이 별도 정산하는 돈이라 애초에 우리 앱이 "처리"할 수 있는 대상이 아니며, Phase 2에서도
계속 "기록"으로만 관리한다.

**Phase 1 범위에 추가**: 원칙상 다음 회기분을 미리 결제해야 하는데 실제로는 나중에 결제하려는
내담자가 있어, 결제가 밀리는 상황을 추적하는 "결제 요청" 기능을 Phase 1에 포함한다. 이미 사용 중인
카드단말기(페이히어)에 카카오 알림톡으로 결제링크를 보내는 "링크 결제" 기능이 있어 새 PG 가맹점
신청 없이 쓸 수 있지만, 공개 문서상 이 기능은 페이히어 앱에서 담당자가 직접 눌러 보내는 수동
방식으로 보이고 우리 CRM에서 자동 호출할 수 있는 API가 있는지는 미확인이다. 그래서 Phase 1에서는
"발송·완료 상태 추적"만 만들고(수동 발송 유지), 페이히어 API 지원 여부가 확인되면 그때 자동
발송·자동확인으로 업그레이드한다(오픈 아이템 참조).

## 전체 아키텍처

```
[관리자 페이지] (dodam-mindcare 저장소 /staff/ 경로, 정적 HTML/JS — 기존 홈페이지와 같은 저장소)
      │  Google 로그인(개인 Gmail) → 허용 이메일 화이트리스트 확인
      ▼
[Google Apps Script Web App]  ← API 겸 비즈니스 로직 레이어
      │                              │
      ▼                              ▼
[Google Calendar — 방 6개 = 캘린더 6개]     [Google Sheets — 도메인 데이터]
 반복/예외 처리는 구글 캘린더 기능을 그대로 사용   내담자·그룹·예약연결·결제·바우처
```

- 예약 생성 시 Apps Script가 해당 방의 구글 캘린더에 이벤트를 만들고, 그 이벤트ID를 Sheets의
  Sessions 레코드에 저장해 내담자·그룹·결제 정보와 연결한다.
- 반복 예약(매주/격주)과 "이번 회차만 수정/취소" 같은 예외 처리는 구글 캘린더의 반복 기능을 그대로
  사용한다 — 직접 구현하지 않는다(버그 위험이 큰 영역이라 검증된 구글 엔진에 위임).
- 화면은 캘린더 데이터 + Sheets 데이터를 합쳐 "선생님별 주간표"로 통합해서 보여준다.

**접근 통제**: 이 저장소는 GitHub Pages 배포 조건상 공개(public) 저장소이므로 `/staff/` 페이지의
HTML/JS 코드 자체는 누구나 볼 수 있다. 하지만 코드에는 비밀키를 두지 않고, 실제 데이터 접근은
① Google 로그인 허용 이메일 화이트리스트 ② Google Sheets/Calendar 자체 공유 권한(같은 화이트리스트로
제한), 이 두 겹으로 막는다. 페이지 URL을 안다고 해도 화이트리스트에 없는 계정은 로그인 단계와 실제
데이터 조회 단계 모두에서 거부된다.

## 사용자 및 권한

- 로그인 대상: 상담사 4명 + 운영자, 각자 개인 Gmail 계정으로 로그인(도담마인드케어 명의의 워크스페이스
  계정 없음)
- **조회**: 로그인한 전원이 전체 일정(모든 방·모든 상담사)을 볼 수 있다 — 방 가용성 확인 목적
- **예약 생성**: 로그인한 누구나 가능(본인이 직접 등록하거나 운영자가 대신 등록)
- **예약 수정/취소**: 제한 없이 로그인한 누구나 어떤 예약이든 수정/취소 가능 (작은 팀이라 상호
  신뢰 기반 — 추후 필요시 "본인 담당 건만 수정 가능"으로 좁힐 수 있음, 지금은 만들지 않음)
- **결제 기록 입력**: 제한 없이 로그인한 누구나 입력 가능

## 핵심 흐름

**예약 생성/수정/취소**
1. 상담사·방·날짜·시간·내담자(또는 그룹) 선택
2. Apps Script가 해당 방 캘린더에서 그 시간대 겹치는 이벤트 존재 여부 확인
3. 겹치면 저장 차단 + "이미 예약된 시간입니다" 안내 (예외 없이 차단 — 사고 예방 우선)
4. 통과 시 캘린더에 이벤트 생성(반복이면 구글 반복규칙 사용) → 이벤트ID를 Sessions에 기록
5. 수정/취소도 동일 경로. 반복 예약 중 "이번 회차만" 변경은 구글 캘린더의 예외처리 기능을 그대로 사용

**결제 기록**
1. 내담자 선택 → 커버범위(회수 또는 기간) 자유 입력, 금액·수단·날짜 입력 → Payments에 기록
2. 화면에는 그 내담자가 커버범위 기준으로 "언제까지/몇 회까지 결제된 상태"인지 계산해서 표시(다음
   결제 필요 시점 파악용)

**바우처 기록**
1. 내담자가 바우처 대상으로 표시돼 있으면 결제 입력 화면에 본인부담금/지원금 칸이 따로 뜸
2. 두 금액 합산 = 총 상담비로 자동 계산·저장. 지원금 입금 여부는 별도 체크(국가 정산 자체는 우리가
   처리하지 않고 "들어왔는지 확인" 용도로만 기록)

**결제 요청(결제링크) 흐름**
1. 다음 회기분이 예정대로 결제되지 않으면 담당자가 해당 내담자로 PaymentRequests에 새 요청을 만듦
2. 담당자가 (지금처럼) 페이히어 앱에서 직접 링크결제를 생성·발송 → CRM에서 상태를 "링크발송함"으로 변경
3. 고객이 결제를 완료하면 담당자가 "완료"로 변경 → 동시에 Payments에 정식 결제기록 추가(커버범위·
   금액 입력)
4. 자동화 아님 — 페이히어 API 지원 여부가 확인되면 1~3 단계를 자동 발송·자동 확인으로 업그레이드
   예정(오픈 아이템 참조)

## 에러 처리

- **방 충돌**: 저장 자체를 막는다(유연하게 풀어주지 않음 — 이중예약 사고 예방이 최우선)
- **로그인 실패/권한 없는 계정**: 접근 거부 화면
- **캘린더-시트 정합성 어긋남**(드물게 캘린더 이벤트는 지워졌는데 시트 기록만 남는 경우 등): 관리자
  화면에 "정합성 점검" 메뉴를 두어 불일치를 찾아 보여준다

## 테스트/검증 방침

- 핵심 로직(방 충돌 검사, 결제 커버리지 계산, 바우처 금액 합산)에 Apps Script 내 assert 기반 자체
  테스트 스크립트를 둔다 — 로직이 깨지면 바로 드러나게
- 화면은 4인 상담사 시나리오(신규 예약, 겹치는 시간 시도, 반복 예약 중 1회만 수정, 결제 기록, 바우처
  결제 기록)를 브라우저에서 직접 실행해 확인
- 대규모 자동화 테스트 스위트는 만들지 않는다(작은 내부 도구 규모에 맞지 않음)

## 오픈 아이템 (구현 중 확인 필요)

- 방 이름 "최지혜 대표원장방"과 "대표방(황성현)"이 유사해 화면 표기에서 혼동 여지가 있음 — 구현
  단계에서 표기를 더 구분되게 다듬을 수 있음(예: "황성현 선생님 방")
- Phase 2(PG 결제 연동) 스펙은 별도 브레인스토밍으로 진행
- **페이히어 링크결제 API 지원 여부 확인 필요** — 고객센터에 문의해서 CRM에서 자동 발송·자동
  결제확인(웹훅)이 가능한지 확인. 가능하면 PaymentRequests 흐름의 2~3단계를 자동화로 업그레이드
